# 关卡与难度曲线

一个好玩具 ≠ 一个好游戏。玩具决定"第 1 分钟好不好玩"，**关卡/难度曲线决定"第 5 分钟还想不想玩"**。实测中最常见的失败：机制有趣，但前 4 关都是 1 步就过 —— 玩家还没发现机制的深度游戏就结束了。

先判断你的游戏属于哪一类，只看对应的部分。

---

## A. 关卡制 / 解谜

### 规则 1：每关只新增一件事，并且必须用到它

列一张"概念表"：机制里有哪些可以组合的元素（对象、规则、例外）。每关**恰好引入一个新概念**，或把两个已学概念**第一次组合**。

| 关 | 类型 | 新东西 | 玩家要意识到 |
|---|---|---|---|
| 1 | 教学 | 核心动词 | "点它会这样" |
| 2 | 教学 | 第一个危险 | "做错会输" |
| 3 | 练习 | — （1+2 组合） | "要先想再做" |
| 4 | 教学 | 第二种元素 | "原来还能这样" |
| 5 | **转折** | 让旧知识**失效**的情况 | "我以为……其实……" |
| 6+ | 组合 | 已学概念两两组合 | |

转折关是解谜游戏的"啊哈点"所在：玩家用前几关学到的习惯会失败，必须换个想法。**没有转折关的解谜游戏就是在做重复劳动**。

### 规则 2：用数字衡量难度，而不是凭感觉

每一关记录（用 `logic-test.mjs` 的求解器自动算，见 `references/testing.md` 第 2 节）：

| 指标 | 含义 | 健康曲线 |
|---|---|---|
| 最少步数 | 最优解要几步操作 | 第 1 关 1 步，之后整体上升；5 关做到 3–4 步 |
| 可选操作数 | 每一步有几种选择 | 逐渐增多 |
| 解的数量 | 多少种操作序列能过关 | **逐渐减少**。后期关卡"乱点能过"的比例 < 10% |
| 陷阱数 | 看起来对但会失败的第一步 | 第 3 关起 ≥ 1 |

连续两关的指标完全一样 = 重复关卡，删掉或改掉。

### 规则 3：设计顺序是倒着来的

1. 先想"玩家需要意识到什么"（这关的啊哈）
2. 再摆出"最少能体现这件事"的布局（元素越少越好）
3. 加一个**诱饵**：最显眼的那个操作恰好是错的
4. 用求解器验证：有解、最优解就是你想的那个、乱点基本过不去

### 规则 3.5：每个元素都必须"有用"（可解性判据）

手写地图最常见的问题：玩家能**绕开**你精心放的门、尖刺、机关直接过关。用求解器逐个检查：

| 判据 | 怎么验证（logic-test 里） |
|---|---|
| 有解 | `solve(lv) !== null` |
| 机关必须参与 | 把这个机关去掉（门改成墙 / 压板删掉 / 特殊规则关掉），再求解 → **无解或最少步数明显变长** |
| 危险必须构成威胁 | 把尖刺/炸弹改成空地再求解 → 最少步数**变短**（说明原来的最优路线被它挡住了）。步数不变 = 它放在没人会走的地方，删掉或挪到最短路上 |
| 转折关的新规则必须是关键 | 关掉新规则后 → 无解 |
| 诱饵有效 | "最显眼的第一步"开头的所有路线都失败，或明显更长 |

```js
// tests/levels.test.mjs 里的"必要性"检查
const without = (lv, fn) => { const c = JSON.parse(JSON.stringify(lv)); fn(c); return c; };
LEVELS.forEach((lv, i) => {
  const base = solve(lv);
  if (lv.doors?.length) {
    const r = solve(without(lv, (c) => { c.walls.push(...c.doors); c.doors = []; }));
    assert(r === null || r.min > base.min, `第 ${i + 1} 关：门必须参与解题`);
  }
  if (lv.spikes?.length) {
    const r = solve(without(lv, (c) => { c.spikes = []; }));
    assert(r && r.min < base.min, `第 ${i + 1} 关：尖刺挡住了最短路`);
  }
});
```

### 规则 3.6：手写不出好关卡时，用"随机生成 + 求解器筛选"

人很难手写出"刚好难"的谜题。可以让电脑随机摆，再用求解器挑出符合指标的：

```js
// tools/gen.mjs —— 用 logic-test 运行：node <skill>/scripts/logic-test.mjs <项目> tools/gen.mjs
export default function (g, assert, log) {
  const { solve, randomLevel } = g;          // randomLevel(cfg)：在 logic.js 里写，按参数随机摆放元素
  const want = { minSteps: 6, maxSteps: 9, maxSolutions: 3 };
  for (let tries = 0, found = 0; tries < 20000 && found < 5; tries++) {
    const lv = randomLevel({ w: 5, h: 6, doors: 1, spikes: 2 });
    const r = solve(lv);
    if (!r || r.min < want.minSteps || r.min > want.maxSteps || r.optimalCount > want.maxSolutions) continue;
    // 再套上面"每个元素都有用"的判据，不满足就 continue
    found++; log(JSON.stringify(lv));        // 把满意的关卡复制进 levels.js，再手工微调
  }
}
```

要点：
- 判据的方向别写反：**帮忙的元素**（门、压板、钥匙）拿掉后变难或无解 = 有用；**挡路的元素**（尖刺、炸弹、墙）拿掉后变容易 = 有用；拿掉后**最少步数完全不变** = 多余
- 求解器要给出 `min`（最少步数）和 `optimalCount`（最优解有几种）；最优解越少，谜题越"有唯一答案"的感觉
- 生成出来的关卡按 `min` 从小到大排列，再按"每关一个新概念"挑选

### 规则 4：数量

- MVP 至少 **6 关**：2 教学 + 1 练习 + 1 新元素 + 1 转折 + 1 组合
- 关卡写在 `levels.js` 的数组里，规则写在 `logic.js`，二者都不依赖画面
- 星级/评分用"步数 ≤ 最优解"或"剩余资源"，不要只用"过没过"

## B. 无尽 / 动作 / 生存

### 规则 1：按"档位"升级，每档加一个**新东西**，不只是"更快"

```
0–15 秒   第 0 档：核心规则 + 基础威胁，让玩家成功几次
15–30 秒  第 1 档：新威胁 A（行为不同，不是换颜色）
30–45 秒  第 2 档：新的场地变化 / 威胁 B
45–60 秒  第 3 档：A + B 组合出现
之后       数值逐步加压（速度、密度），带上限
```

**硬性要求**（阶段 2、3 的闸门会检查）：
- **核心规则（啊哈点）在 10 秒内出现**。不要把最有意思的规则藏到第 1 档以后，前 20 秒只是"普通收集游戏"的话，玩家在看到它之前就走了
- 第 1 档 ≤ 20 秒开始；**第 3 档 ≤ 60 秒开始**；相邻两档间隔 ≤ 20 秒
- 至少 4 档（第 0–3 档），每档有新内容

档位的标准写法：

```js
// config.js —— 每档只写"这一档新增/改变了什么"，代码累积读取
tiers: [
  { at: 0,  name: '',          spawnEvery: 1.2 },                       // 第 0 档不显示横幅
  { at: 15, name: '猎手出现!',  hunters: true },
  { at: 30, name: '黑洞!',      holes: true, spawnEvery: 1.0 },
  { at: 45, name: '全都来了!',  hunterSpeed: 1.3 },
],
// game.js
tierAt(t) { let k = 0; CFG.tiers.forEach((x, i) => { if (t >= x.at) k = i; }); return k; },
cur() { return Object.assign({}, ...CFG.tiers.slice(0, this.tier + 1)); },   // 合并到当前档的所有设置
// update 里
const k = this.tierAt(this.elapsed);
if (k !== this.tier) { this.tier = k; G.debug.tier = k; if (CFG.tiers[k].name) this.showBanner(CFG.tiers[k].name); G.sfx('powerup'); }
const T = this.cur();   // T.hunters、T.spawnEvery ...
```

- 每次换档：横幅提示（`UI.banner`）+ 音效，让玩家知道"变了"
- 当前档位写进 `G.debug.tier`，bot 测试才能确认后期内容真的出现了；所有档位时间都从 `CFG.tiers[i].at` 读，测试才能用 `--init` 压缩
- **公平**：新威胁第一次出场时要有预警（`UI.icon('warn', ...)` 或屏幕边缘的 `arrow` 指向来向，提前 ≥ 0.6 秒），并且出场前 2–3 秒减少其它刷新

### 规则 2：难度要能被"技术"抵消

如果随机乱按也能活很久，说明没有需要判断的东西。检查：
- 有没有**需要时机**的操作（太早/太晚都不好）？
- 有没有**风险换收益**的选择（靠近危险得分更多、连击中断）？
- 用 bot 测：策略 bot 的得分和存活时间都明显高于随机乱按（标准见 `references/testing.md` 3.3）

### 规则 3：张弛

一直加压会让人疲劳。每升一档之前给 2–3 秒的"喘息"（刷新变少），让玩家看清新东西出场。

## C. 写进 GDD

GDD 第 6 节必须填一张表：关卡制填"关卡表"（每关的新概念、诱饵、预期最少步数），无尽模式填"档位表"（时间、新内容、数值）。**填不满 6 行说明机制还不够深，回到阶段 1 步骤 4 再强化扭转。**
