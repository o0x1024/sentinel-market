# 阶段 2：设计

目标：把创意变成**可以直接照着写代码**的一页文档 `GDD.md`。

## 步骤

1. 创建项目（会自动复制 GDD 模板）：
   ```bash
   bash <skill目录>/scripts/new-game.sh <项目目录> "<游戏名>"
   ```
2. 按 `GDD.md` 的模板逐项填写。每一项都要填（第 0 节在阶段 1 已经填好）。
   填第 6 节难度曲线之前先读 `references/level-design.md`；填第 10 节测试计划之前先读 `references/testing.md` 第 0 节。
3. 对照下面的"设计规则"自查，不符合就修改。
4. 读 `references/art-styles.md` 第一节，按游戏类型和题材**选定画风**，写进 GDD 第 8 节和 `config.js` 的 `art: { style: '...' }`。先看 `references/img/art-all.jpg`。
5. 把所有数值（速度、间隔、尺寸）的**初始猜测值**写进 `config.js`。参考 `references/game-feel-numbers.md`；物体尺寸按 art-styles.md 第四节。

## 设计规则

**操作**
- 主操作必须能用**一根手指**完成（点击 / 按住 / 拖拽 / 滑动选一种）
- 不要用虚拟摇杆加按钮；如果需要移动，用"拖拽跟随"或"点击目标点"
- 触摸目标不小于 80×80 逻辑像素

**节奏**
- 从点开游戏到开始操作：≤ 1 次点击
- 前 10 秒必须让玩家成功至少一次
- 失败到重开：≤ 1 秒、1 次点击
- 一局 30–180 秒

**可读性**
- 好东西和坏东西用**颜色 + 形状**双重区分（色盲也能玩）
- 屏幕上同时出现的对象类型 ≤ 4 种
- 玩家角色（或玩家直接操作的东西）是画面上最亮、最显眼的东西

**范围**
- MVP 只做 1 个核心机制 + 1 种失败方式 + 计分
- 对象类型 ≤ 4 种，场景 ≤ 4 个
- 关卡制：先做 6 关（含 1 个转折关），关卡数据放 `levels.js`，规则放 `logic.js`（不依赖画面，便于求解器验证）
- 无尽：至少 4 档，每档有新内容
